# Java设计模式

## 概念

设计模式是对常见设计问题的经验总结，不是固定模板。常见分类包括创建型、结构型、行为型。创建型关注对象创建，例如单例、工厂、建造者；结构型关注对象组合，例如代理、适配器、装饰器；行为型关注对象协作，例如策略、模板方法、观察者、责任链。

学习设计模式时不要只背 UML，要结合业务变化点理解它解决了什么耦合问题。

## 学习重点

- 先识别业务边界、数据边界和部署边界。
- 关注可扩展性、可用性、一致性、成本和复杂度。
- 架构方案需要能落地到接口、数据、监控、发布和应急预案。

## 使用场景

- 面试复习时，用于梳理概念、边界和常见追问。
- 项目开发时，用于判断技术选型、代码写法和排查方向。
- 线上问题处理时，用于快速定位相关模块和可能风险。

## 常见问题

- 为了使用模式而使用模式，让简单代码变复杂。
- 只背类图，不理解变化点和扩展点。
- 单例、工厂、策略等模式滥用静态状态，影响测试和并发安全。

## 总结

设计模式的价值在于管理变化和依赖。判断是否需要模式，应看它是否降低耦合、提升扩展性，并让代码更容易理解。
