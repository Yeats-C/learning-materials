# Java与UML建模

## 概念

Java与UML建模 属于系统设计与架构能力范围。架构设计不是堆技术名词，而是在业务目标、团队能力、成本约束和系统质量之间做权衡。

评价一个架构方案，应关注边界是否清晰、数据是否一致、故障是否可控、扩展是否平滑、监控是否完整、上线和回滚是否可执行。

## 学习重点

- 先识别业务边界、数据边界和部署边界。
- 关注可扩展性、可用性、一致性、成本和复杂度。
- 架构方案需要能落地到接口、数据、监控、发布和应急预案。

## 使用场景

- 面试复习时，用于梳理概念、边界和常见追问。
- 项目开发时，用于判断技术选型、代码写法和排查方向。
- 线上问题处理时，用于快速定位相关模块和可能风险。

## 常见问题

- UML 图过细，维护成本超过沟通收益。
- 类图和实际代码长期不一致。
- 只画静态结构，不表达关键业务流程和状态变化。

## 总结

Java与UML建模 的落地标准是能指导模块边界、数据流、部署、监控和故障处理，而不是只停留在概念图。
